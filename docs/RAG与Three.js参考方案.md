## 推荐首版：3D 检索来源图

目标：让用户看清“本轮回答用了哪些资料，Agent 是否进行了补查”，点击可验证原文。展示的是实际检索记录，不是模型内部思维。

节点与边来自真实数据：

- 问题节点：当前用户问题，关联本轮 runId。
- 检索节点：首次检索、子问题检索与补查，关联 stepId 和实际状态。
- 片段节点：本轮召回的 chunkId，携带来源文件、位置与排名。
- 文档节点：片段所属的 documentId。
- 边只表示本轮执行、命中和文件归属；回答引用另用已验证 citationId 高亮。

首版使用按轮次、文档分组的稳定布局，不需要降维或实体抽取。三维位置只用于排布，不代表真实语义距离。界面名称用“检索来源图”，不能把它称作已经实现 GraphRAG。

交互建议：

1. 在回答来源区提供“查看检索路径”入口，按需打开侧栏或全屏视图，默认仍看聊天。
2. 拖动旋转、缩放；悬浮显示文件名与片段摘要，触屏用点选完成相同操作。
3. 点击片段后聚焦节点，在普通 DOM 面板展示原文、页码/标题和引用状态。
4. 按文件或检索轮次筛选；区分召回片段与最终引用片段。
5. Agent 补查时追加真实步骤，失败显示失败，不能用预设动画假装已完成检索。
6. 可回看已持久化的调用记录；不因此承诺刷新后生成仍在后台执行。

延续云白编辑台的浅色背景与紫灰配色、深色模式；标签和长文本放在 HTML 中，减少重叠。首版只展示本轮检索子图，并设置节点上限及“已省略”提示，不一次加载整个知识库。

## 两个可选后续方向

| 方向 | 使用价值 | 额外成本 | 建议 |
| --- | --- | --- | --- |
| 3D 语义分布图 | 按文档着色探索分块分布，查看查询命中位置 | 降维、投影版本、采样与坐标缓存；需处理新增文档后的布局变化 | 第二阶段再评估 |
| 3D 文档目录 | 知识库 / 文档 / 章节以层级节点展开，点击资料后继续提问 | 能复用元数据，但大量标题容易遮挡，须保留列表 | 可作为来源图的浏览模式 |

语义分布图可借鉴 Project Golem，但必须用同一投影模型映射资料与查询；不能每次单独投影后把坐标直接混在一起。实际召回与排名始终基于原始向量和权限条件，不能改用降维后的三维距离。降维可视化不证明相关性、因果关系或回答正确性。

不优先做常驻的 AI 球体或数字人：对当前文件问答链路帮助有限，且会增加持续动画与资产工作。若以后增加语音交互，可以重新评估。

## 实现边界

- 首选 `three + @react-three/fiber@9 + @react-three/drei`，安装时再核对兼容版本；也可以选择 react-force-graph-3d 快速做原型。二者是替代路径，不为同一视图叠加两个渲染器。
- 按需加载客户端 3D 组件；关闭视图时释放资源，静止时按需渲染。批量节点再考虑 InstancedMesh，性能策略参考 [R3F 官方指南](https://github.com/pmndrs/react-three-fiber/blob/master/docs/advanced/scaling-performance.mdx)。
- SSE 只推检索步骤、片段 ID 和状态等变化，不在每个 Token 到达时重建整个场景。
- 图接口同样检查会话与文档授权；不要把全库向量或无权访问的文件信息发送到浏览器。
- 保留等价的来源列表与键盘操作；移动端默认列表，支持 3D 的设备可主动切换。WebGL 不可用时仍可完成问答和原文查看。
- 分别测量关闭/打开 3D 时的加载开销、交互帧率、内存与聊天输入响应；当前没有实测性能数据，不写帧率或规模承诺。

## 建议演示与实施顺序

先完成现有方案中的真实 RAG 与引用；随后用这些结果做来源图，再把 Agent 的子问题与补查记录接进同一视图。用户尚未选择 3D 方向，本文件不将建议自动升级为已确认交付。

演示流程：上传两份公开文档 -> 提出跨文件比较问题 -> Agent 分别检索并在证据不足时补查 -> 回答附引用 -> 打开 3D 来源图 -> 点击已引用片段查看原文。

完成并验收后，可在简历中说明：基于真实检索与执行事件构建 Three.js 来源视图，实现节点拾取、相机聚焦、来源联动、按需渲染及移动端降级。只有实际实施和测量后再写具体实现与性能结果。
