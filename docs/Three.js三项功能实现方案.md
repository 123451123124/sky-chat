# Sky Chat：证据探索、语义地图与对话分支实现方案

日期：2026-10-20。状态：实现设计，新增功能尚未按本文实施。

用户已确定优先建设场景 **1「回答证据探索」、3「知识库语义地图」、4「对话分支地图」**；场景 **2「可交互三维讲解」、5「AI 形象与语音反馈」**作为未来扩展。本次仅交付文档，不安装依赖、不修改业务代码、不执行数据库迁移。

本文以当前工作区代码为基线。旧文档 [RAG 与 Three.js 参考方案](RAG与Three.js参考方案.md) 保留早期调研；功能范围、优先级和后续实施以本文为准。

## 1. 目标与交付边界

| 场景 | 解决的问题 | 本轮计划交付 | 使用位置 |
| --- | --- | --- | --- |
| 1. 回答证据探索 | 引用了什么、从哪里找来、如何核对 | 引用定位、路径聚焦、文件/步骤/引用筛选、原文联动与执行记录回看 | 聊天来源面板 |
| 3. 知识库语义地图 | 资料如何分布、查询命中了哪些区域 | 版本化点云、文件着色、查询投影、实际命中高亮与片段详情 | 管理端检索实验台 |
| 4. 对话分支地图 | 从哪里分出去、回答有哪些版本、如何返回 | 持久分支关系、回答版本、会话树、消息路径展开与定位 | 聊天工具栏与历史导航 |

三个场景均采用“列表/树形导航 + 主动打开的 3D 视图 + 普通文本详情”。桌面支持完整图形，手机默认使用等价列表；关闭 3D 不影响聊天。

证据图展示检索关系；语义地图展示向量的近似分布；分支地图展示用户操作产生的会话关系。三种边分别定义，不合并为泛化的“知识图谱”。

## 3. 总体架构与技术选择

沿用现有 `three + @react-three/fiber + @react-three/drei`，不叠加另一套 3D 图渲染器。React、Zustand、SSE、Prisma/PostgreSQL 和现有检索运行时继续承担各自职责。

```text
回答与 rag-trace → 证据适配层 → 来源图 / 来源列表 → 原文面板
有效叶向量 → 投影任务 → 版本化坐标 → 语义点云 / 命中列表
会话、消息版本、分支记录 → 分支适配层 → 会话树 / 3D 地图 → 消息定位
```

共享设施仅抽取相机聚焦、选择状态、主题、错误降级和资源释放；各场景独立构造节点及业务操作。先改造证据图，再根据实际重复代码抽取公共组件，不先建设通用图引擎。

- 引用选中键为 `runId + sourceId`；分支定位键为 `sessionId + messageId + revision`；地图点键为 `projectionId + chunkId`。
- 3D 选择状态放在对应面板，与聊天 Token 缓冲分离；文本增量不重建整个场景。
- 同页最多激活一个重型 3D 面板。关闭时卸载 Canvas，释放纹理、几何体、材质、监听器和计算任务。
- 每个图提供复位、定位当前对象、图例和等价文本导航；不靠颜色表达全部状态。

## 4. 场景 1：回答证据探索

### 4.1 用户流程

1. 点击回答中的引用打开“回答依据”，默认列表；保留用户本次打开后的视图选择。
2. 选中准确的 runId/sourceId。切换 3D 后，相机聚焦该片段、文件和关联检索步骤组成的路径。
3. 切换“全部召回 / 回答已引用 / 未引用”，再按文件或步骤筛选；条件以 AND 组合，并显示可见数量。
4. 选择步骤显示工具、实际查询、状态、耗时和命中数；选择片段显示原文、页码/标题、引用状态和文件版本。
5. “返回引用位置”关闭遮挡面板并滚动至引用；虚拟消息列表先定位消息，再定位具体锚点。
6. 同一来源多次出现时记录本次点击的 occurrence；从图反向定位时列出引用位置。未引用片段只提供“返回回答”。

引用 ID 校验只能证明来源属于本轮召回，不能证明附近每句话都受原文支持。首版按显式引用锚点关联，不由模型或简单正则猜测语义证据关系，不显示“已证明”或“置信度百分比”。

### 4.2 图形表达与联动

- 保留四层结构，横向表达执行/来源关系，纵向分组，少量深度区分轮次或文件组；图例明确坐标不代表相关度。
- 布局按稳定业务顺序缓存。新步骤追加到预留位置，选择、筛选和新增边不打乱已有节点。
- 高亮选中路径，其他节点淡化；召回/引用同时使用文字或形状标记。
- 相机聚焦使用有限动画；减少动画偏好下直接跳转。完整原文始终在 DOM 中阅读和复制。
- 筛选隐藏选中项时清空选中状态并提示，不能继续展示与图不一致的旧原文。
- 边仅表示真实执行、命中和文件归属。失败、取消、运行中保留实际状态，不播放伪造成功流程。

### 4.3 数据与历史兼容

扩展 RagTrace 的可选 schemaVersion，旧记录按 v1 解析。RagSource 增加可选 documentRevision、matchedChunkIds、scoreKind。当前 score 可能来自不同检索阶段，必须标明含义，不统一当概率。

父上下文回填时，chunkId 保留展示的父片段，matchedChunkIds 保存原始叶命中。语义地图只给叶片段建点，通过显式映射联动；旧记录无映射时提示“历史记录缺少叶片段位置”，不伪造坐标。

原文读取沿用 `/api/documents/[id]?chunkId=...` 并检查当前权限。新版本不能替换旧来源 ID；旧版本存在且可读则标记“历史版本”，否则显示不可用。

统一处理 AgentRun 接口、历史消息返回和复制分支快照中的来源元数据：

- 校验记录/会话归属，并按当前文件权限决定是否返回文件名、摘要与原文。
- 已失效来源显示“资料当前不可用”，只保留必要引用标识与拓扑，不从旧快照重新暴露无权读取的摘要。
- 已保存回答正文保留；上述规则约束来源面板及接口重新返回的资料数据。
- 分支复制的 RAG parts 标记“历史副本”，不伪装为新 AgentRun。源 run 被删时可显示经授权裁剪的快照，无须创建虚假执行记录。

### 4.4 验收

- 同一回答重复引用、不同回答都含 S1 时，选择、路径与回跳准确。
- 首检和补查命中同一片段，显示一个片段与多条真实边。
- 刷新恢复已保存记录；停止生成后仅保留已发生步骤。
- 组合筛选正确；空结果、失效来源、失败、取消均有文本状态。
- WebGL 失败、手机及键盘下仍能筛选、查看原文和返回引用。

## 5. 场景 3：知识库语义地图

### 5.1 产品范围

首版在 `/admin/rag` 增加“语义地图”，只允许管理员操作自己拥有的单个知识库，与现有检索实验台的所有权约束一致。聊天端全库地图、跨库混合投影后续评估。

先选知识库生成地图，再输入查询。点按文件着色，支持文件/标签筛选；实际命中点增加外圈或形状标记，右侧显示真实排名、片段和原文入口。悬浮仅展示短标签，全文点选后读取。

固定说明：“三维位置是高维向量的近似投影；实际召回和排序依据原始向量、全文检索与重排。”首版不自动命名主题，不将邻近点标为重复文档，不把聚团解释为准确率或覆盖率证明。

### 5.2 投影算法

首版采用 **PCA 三维投影**，优先保证可复现及新查询使用同一变换；UMAP 作为后续替换算法。`ml-pca` 提供拟合及新样本投影，可作为候选；正式接入前核对实际版本、许可证、耗时与内存。

1. 服务端筛选本库 ready、isCurrent、leaf、embedding 非空且配置有效的授权片段。
2. 检查维度、有限数值和非零范数，L2 归一化。按文件分层、再按稳定哈希抽样，固定种子和排序。
3. 最多 1,000 个样本拟合，最多 5,000 个基础点进入地图。超限显示有效总数、点数和抽样规则，抽样后文件点数不冒充真实文件大小。
4. 使用训练均值和前三主成分计算 `y = (normalize(x) - mean) × components`，保存变换与各轴展示尺度。
5. 每轴绝对值最大的 loading 取正以统一符号；拟合样本、依赖版本及参数参与版本标识。同一 projectionId 的坐标冻结。
6. 查询使用相同 embedding、归一化、均值、主成分和尺度，不单独拟合查询，不按本次查询重缩放整张地图。
7. 显示前三轴解释方差之和。少于四个样本或有效秩不足三时明确标记维数，使用平面/线性展示，不填随机坐标。

PCA 可能压缩语义差异，查询也可能落在点云外。通过包含查询的相机视角处理，不裁掉或篡改位置。换算法必须生成新投影版本，继续遵守同一变换与坐标冻结规则。

### 5.3 实际命中映射

查询调用现有 searchKnowledgeDetailed，再用保存变换投影查询向量。高亮以真实返回 ID 为准：

- 检索范围是筛选后授权文件/标签的完整集合，不是抽样点集合。
- 未被地图抽样包含的实际叶命中，用同一 PCA 临时投影为 overlay，标注“本次命中补充点”，不改变基础地图。
- 返回父上下文时通过 matchedChunkIds 找到叶命中；父片段在详情中展示，不误画成有叶向量的点。
- 已删除片段、不同文件版本、不同向量配置不能按名字匹配旧点，提示刷新地图。
- 查询响应携带 projectionId/requestId。快速切换查询或知识库时取消旧请求，拒绝跨版本叠加。
- 向量服务失败而混合检索仍有全文结果时，保留真实命中列表并提示“查询位置暂不可用”；不制造查询坐标。具备有效叶向量的命中仍可定位，缺少向量的结果仅列在详情中。

### 5.4 后台任务与数据模型

新增独立投影 worker，复用 PostgreSQL 队列/租约模式。拟合放入 worker thread，父进程保持心跳；不得在 Web 请求或入库 worker 的事件循环中同步拟合。初始并发 1、任务预算 120 秒，超时终止计算并可重试；这些为待测控制值。

| 计划模型 | 主要字段和约束 | 用途 |
| --- | --- | --- |
| SemanticProjection | id、userId、knowledgeBaseId、requestId、scopeFingerprint、corpusFingerprint、embeddingProfile、pipelineProfile、algorithmVersion、status、transform、sampling、explainedVariance、counts、createdAt；唯一 (userId, requestId) | 版本、构建幂等及服务端变换 |
| SemanticPoint | projectionId、chunkId、documentId、documentRevision、x/y/z；唯一 (projectionId, chunkId)，索引 documentId | 持久坐标 |
| ProjectionJob | projectionId 唯一、status、attempts、leasedBy、heartbeatAt、availableAt、errorCode | 排队、恢复、重试 |

SemanticPoint 与 Chunk/Document 外键级联清理；Projection 随所属知识库/用户删除。已完成版本不原地改写，新版成功后才切默认版本。

通过数据库唯一任务键对“所有者 + 知识库 + 语料/范围/算法指纹”去重在途构建，不能只在进程内查重；失败重试复用同一任务，主动重建仅在新指纹或明确新版本时创建投影。每页读取都校验投影仍有效，分页期间失效即终止本次加载。

指纹包含排序后的文档 ID/revision、叶 ID/textHash、向量/分块配置、抽样和算法版本；范围指纹包含请求者与有效资料范围。创建、执行、提交结果、读取及查询时重新核对归属、范围和指纹。

角色撤销立即拒绝；文件移出、删除、重索引、版本替换或配置变化使旧地图 stale。过期返回 409、“资料已变化，请重建地图”，停止返回旧点与旧统计。构建中语料变化则丢弃结果；失败不影响检索，仍有效旧版可用，过期旧版不能继续返回。

浏览器不接收原始高维向量、训练样本和变换参数，只拿必要点元数据。全文按点击读取，响应使用私有、禁止共享缓存策略。

### 5.5 验收

- 同一 projectionId 刷新、查询、筛选后基础坐标一致；重启可恢复并投影新查询。
- 查询与某片段向量相同时投影位置一致；客户端展示与服务端坐标在容差内一致。
- 高亮 ID 与真实混合/重排结果一致，未抽样命中和父上下文映射正确。
- 覆盖零/少量/重复/低秩向量、超时、重复构建、worker 中断及语料变化。
- 他人知识库、撤销权限、删除/替换资料不能返回旧点、摘要或统计。
- 显示抽样、维数及近似性质；关闭地图不影响检索实验台。

## 6. 场景 4：对话分支地图

### 6.1 用户行为

工具栏增加“对话地图”，默认展示当前分支家族的会话树。3D 以时间、分支、回答版本组织空间；会话默认折叠，展开才显示消息路径和分叉位置，避免全部正文进入场景。

选中节点在普通详情区预览消息、时间和版本。“打开此处”切换会话并定位；从旧回答版本继续时创建新分支，不改变原会话后续上下文。

- “从这里继续”：复制截至选定消息的上下文为独立新 Session，记录精确分叉版本。
- “重新生成”：仍更新末尾问题对应的回答，旧回答进入版本历史；只允许末尾回答，避免让后续上下文失真。
- 查看旧版本为只读预览。“设为当前版本”限末尾回答、无进行中请求；从中间历史版本继续必须建分支。
- 分支再分支形成真实父子关系，不用内容相似度猜测连线。
- 切换版本同步切换 content 和 RAG parts，不混合不同版本的文字、工具和引用。

### 6.2 数据模型

保留“独立 Session + 线性 Message”，增加版本与分支，不将存储改写为共享前缀 DAG。

| 计划变更 | 约束与用途 |
| --- | --- |
| Session.branchFamilyKey | 服务端生成，新分支继承；查询仍限定 userId，家族键不提供授权 |
| Message.ordinal | 会话内稳定递增；唯一 (sessionId, ordinal)，用于排序及前缀复制 |
| Message.revision | 当前展示内容的版本号；content/parts 保留当前版本读取兼容 |
| Message.writeVersion | 单调递增写入锁版本，切回旧内容也递增，避免并发标记倒退 |
| MessageRevision | messageId、version、content、parts、status、createdAt、requestId；唯一 (messageId, version) 与 (messageId, requestId) |
| SessionBranch | childSessionId 唯一、parentSessionId/anchorMessageId/anchorRevisionId 可空、forkOrdinal、anchorSnapshot、userId、requestId、createdAt |

MessageRevision 随消息删除。SessionBranch 随 child Session 删除；parent/anchor 删除 SetNull，留下来源已删除状态及最小锚点快照。`(userId, requestId)` 唯一保证分叉重试不重复建会话。

快照只保留必要短文本、位置和版本，不复制无权读取的原文。对其他仍存活的分支也有引用的祖先会话删除时，清除其导航快照中的父标题/文本，仅保留缺失来源标识。

子消息拥有新 ID/ordinal，可保存可空 originMessageId/originRevisionId 供导航，源删除时置空。复制正文仍保留；历史 RAG parts 按第 4.3 节裁剪并标记历史副本，不复制执行记录。

家族键保留同源关系；父删除后允许多个根，显示“部分来源已删除”。不得级联删除独立子会话。

### 6.3 服务端分叉事务

新增专用接口；客户端只提交锚点、版本和操作 ID，不把整段复制历史作为权威数据。

1. 校验父会话归属、锚点归属、版本存在且消息已保存；生成/保存期间禁用分叉。
2. 使用 Serializable 事务按 ordinal 读取前缀。锚点用选定 revision，其他消息使用同一事务快照中的当前版本，校验条数和字节预算；序列化冲突做有限重试，仍冲突返回 409。
3. 创建子 Session、复制消息及初始版本、写 SessionBranch。使用一致性事务和 expectedWriteVersion 检查并发变化，冲突返回 409，不静默复制另一版本。
4. 继承父会话当前仍有权读取且就绪的资料，最多现有 12 个；失效项不继承并提示，不影响复制已保存聊天正文。
5. 成功提交后返回子会话及资料范围。相同 requestId 重试返回已创建结果；不能留下部分消息或悬空关系。
6. 客户端仅成功后切换；失败保留当前会话、草稿和消息。

初始复制预算为 1,000 条消息且 content/parts 序列化总量不超过 2 MiB。超限返回 413，提示选择更早分叉点，不静默截断。

### 6.4 回答版本与并发

生成前保留旧答案，创建 generationRequestId。保存重生成结果时提交 expectedWriteVersion；事务验证写入锁版本，插入新 MessageRevision，再更新 Message 当前内容、内容版本号和写入锁版本。

- 相同 generationRequestId 重复保存返回同一结果；不同并发请求冲突返回 409。
- 初始回答同样写入 v1；普通新增消息分配 ordinal 也须在服务端原子完成。
- 停止/断流保留部分回答，revision.status 标注 partial/cancelled；不能提前删除旧版本或以空内容覆盖它。
- 切换会话后旧请求返回不能污染新会话；冲突时给出可恢复提示。
- 版本切换只接受已有版本 ID，不能接受客户端任意正文；同步替换对应 parts，writeVersion 继续递增。

### 6.5 迁移、删除与定位

- 旧会话按 createdAt、id 回填 ordinal；现存回答建立 v1；每个旧会话独立 familyKey。
- 无可靠父关系的历史分支先作为独立根；已覆盖回答无法恢复，界面注明版本记录从上线后开始。
- 分批、幂等回填，验证行数和唯一性后切读写；回填期暂停相关写入或使用双写保护，避免分配冲突序号。
- 打开目标先加载会话，再让虚拟列表定位消息，最后切换版本并高亮。深链接可带 sessionId/messageId/revision，读取仍必须服务端授权。
- 删除父会话不删除子会话；删除子会话不影响兄弟节点。
- 公开分享只输出当前所选会话现有内容，不默认公开家族、旧版本或兄弟会话。

### 6.6 验收

- A 的第 3 条消息创建 B，B 再创建 C，刷新后结构、前缀和分叉版本一致。
- 重生成前后版本都可看；旧版文字/引用一致；旧版继续不改原后续消息。
- 双击与重试只创建一次；失败不改变原会话；并发冲突不覆盖其他回答。
- 删除 A 后 B/C 仍可用并提示来源缺失；删除子节点不影响兄弟。
- 伪造他人 session、anchor、revision、familyKey 均不能访问。
- 长路径分页展开；手机/键盘能完成同样导航；分享不泄漏历史。

## 7. API 与改动清单

下表为计划契约。编写代码前核对本地 Next.js 文档及现有接口风格。

| 接口 | 请求重点 | 返回重点 |
| --- | --- | --- |
| 增强 GET /api/agent-runs/[id] | runId | 版本化、按现权限裁剪的 trace |
| POST /api/admin/semantic-maps | knowledgeBaseId、requestId | 202、projectionId 和任务状态；同指纹在途任务复用 |
| GET /api/admin/semantic-maps/[id] | projectionId | 状态、版本、抽样与维数说明，不含 transform |
| GET /api/admin/semantic-maps/[id]/points | cursor、limit（最多 1,000） | 稳定排序点、nextCursor；基础点共最多 5,000 |
| POST /api/admin/semantic-maps/[id]/query | query、mode、topK、文件/标签筛选、requestId | projectionId、queryPosition、真实命中和 overlay |
| POST /api/admin/semantic-maps/[id]/retry | 失败任务操作 ID | 幂等重试；语料变化改建新版 |
| POST /api/session/[id]/branches | messageId、revision、expectedWriteVersion、requestId | 子会话、复制消息、继承资料和失效提示 |
| GET /api/session/[id]/branch-map | cursor、展开会话、分页大小 | 本人家族节点/边，不带全部正文 |
| GET /api/message/[id]/revisions | cursor、limit；传 revision 时读取指定版本 | 授权版本列表先摘要；指定版本返回完整 content/parts |
| PATCH /api/message/[id]/active-revision | revision、expectedWriteVersion | 当前版本；仅末尾回答可切换 |
| 增强 POST /api/message | expectedWriteVersion、generationRequestId | 幂等版本保存，兼容普通新增 |

统一 Schema 校验。401 未登录、403 功能角色不符、404 对象不存在/无权访问、409 版本/语料冲突、413 复制超限、503 服务暂不可用。任务失败返回真实错误状态，不伪装为空地图。

语义查询每管理员最多一个在途请求，构建任务首版全局并发 1，按 requestId/指纹去重；查询超时复用现有模型请求约束及 embedding 缓存。取消查询不取消地图，构建失败不影响聊天。

建议新增模块：

```text
components/three/             按需 Canvas、相机聚焦、主题、降级
lib/visualization/            公共 ID/选择契约，不放权限
lib/rag/evidence-view.ts      trace 适配、筛选、历史权限裁剪
lib/rag/projection/           拟合、变换、任务、指纹、采样
lib/conversation/             分支事务、回答版本、地图数据、布局
scripts/projection-worker.ts  独立投影 worker
app/chat/components/         证据详情及分支地图
app/admin/rag/               语义地图与查询面板
```

## 8. 性能、可用性与观测

| 视图 | 初始规模 | 策略 |

测量首次打开、数据/计算/渲染阶段耗时、交互帧率、长任务及 WebGL 丢失；对比开关 3D 时输入、流式输出和滚动响应；连续开关 20 次检查资源是否持续增长。报告注明设备、浏览器、节点数与版本；监控不上传问题、文件名、摘要或完整向量。

WebGL 不可用、上下文丢失和组件异常回退列表。worker 未运行显示等待/启动指引。支持 Escape 关闭、焦点返回、键盘导航、减少动画、手机及深浅色。

## 10. 验证与演示

必要验证：

- 纯逻辑：图 ID、组合筛选、路径、变换、采样、指纹失效和树布局。
- 数据集成：分支原子性、幂等、版本并发、外键删除、权限撤销和任务租约。
- 浏览器：引用/图/原文联动，刷新、旧版继续、手机/键盘/WebGL 降级、旧请求不污染新状态。
- 迁移：使用虚构数据副本验证行数、正文/parts、唯一性及重复运行，不对真实账号做破坏性测试。
- 回归：现有核心/RAG/Agent 测试、lint、TypeScript、生产构建；UI 变更运行相关浏览器用例。仅本次文档改动无需运行这些业务测试。

演示步骤：

1. 三份虚构项目资料进行跨文件比较，点击引用、筛选实际引用、查看补查/原文并回跳。
2. 创建两个分支，对其中一个重生成；刷新后看旧版，再从旧版创建第三个分支。
3. 管理员生成地图，查询两个主题，对照真实命中 ID，展示未抽样 overlay。
4. 更新资料，展示旧地图失效和重建；历史回答仍指向历史来源。
5. 撤销资料访问、模拟 WebGL 失败、切换手机，验证权限提示和等价导航。

报告区分功能、权限和性能，注明样本/设备；未测量前不写“万级节点流畅”“提升准确率”等结论。
