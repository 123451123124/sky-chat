# Sky Chat：面向 AI 全栈简历的改造方案

状态：首版已实现，实际能力与部署以 [RAG使用与部署.md](RAG使用与部署.md) 为准。2026-10-19 按用户要求取消 MCP、暂缓产品 Skill，实现通用 RAG、单 Agent 检索增强与 Three.js 来源图。下文保留改造设计，其中混合检索、30–50 题评测及更多性能实验仍未完成，不应当作既有成果。

## 产品目标

Sky Chat 保持通用 AI 聊天客户端定位，增加文件与知识库问答，以及围绕检索的单 Agent 能力。继续使用当前聊天工作台，普通聊天、模型切换、会话管理等已有功能保持可用。

演示主线：上传普通 PDF/Markdown/TXT -> 选择当前会话附件或已保存的知识库 -> 提问 -> 必要时理解追问、拆分问题、补充检索 -> 返回带来源的流式回答 -> 点击查看命中片段。文件可以是论文、产品手册、学习材料或公开项目文档，不绑定专用业务领域。

参考选型已整理在 [GitHub-RAG设计调研.md](GitHub-RAG设计调研.md)。首选参考 Open WebUI 的 RAG 产品入口、LibreChat RAG API 的文档范围过滤和 AnythingLLM 的文件处理分层。

仅使用有权处理的文档作为演示资料；不导入实习公司的非公开材料。演示问题、基准题和报告标注为样例。

## 一、先完成可溯源的 RAG

产品分为两个入口：会话附件用于当前会话；知识库可跨会话复用，且必须显式选择。两者共享解析、向量化、检索和引用服务，不为不同业务另做一套 RAG。会话附件仍可持久化以支持刷新恢复，“会话范围”不等于“只存内存”。

服务：继续使用 Supabase PostgreSQL，扩展 pgvector；文件存储、元数据与向量分开。对话模型沿用当前通义配置，Embedding 独立配置。实际验证当前账号/Key 的 Embedding 与可选重排模型权限后再锁定模型与向量维度。

入库链路：

1. 上传 PDF / Markdown / TXT，生成 documentId、版本和内容哈希；保留原文件或可下载对象。
2. PDF 解析保留页码，Markdown 保留标题路径。按结构切分，再用 Token 长度限制和适量重叠处理长段落。
3. 后台任务分批生成 Embedding，保存 Chunk、位置元数据、模型与维度版本。相同内容与模型版本去重；失败可重试。
4. 前端展示“等待、解析、向量化、就绪、失败”及可操作的错误，刷新后仍能查询任务。

查询链路：在用户有权访问的知识库内召回 -> 必要时重排 -> 限制上下文预算 -> 注入带固定引用 ID 的原文片段 -> 回答中生成引用 -> 验证引用 ID 确实来自此次召回 -> 点击打开文档与定位片段。证据不足时明确说明缺失信息。

第一版先做向量召回及引用。随后根据评测加入关键词检索和 RRF 融合，重排作为对照实验，不先堆全部组件。中文材料要明确分词/索引策略，不能照搬英文全文检索配置；Postgres 全文排名也不能直接称为 BM25。

权限必须在 SQL 查询阶段加入 userId / knowledgeBaseId 条件，身份来自服务端认证上下文。当前应用使用自有认证和 Prisma 数据库连接，不能假设开启 Supabase RLS 就会自动获得用户隔离。

验收：跨文件问题命中正确来源；引用可定位；无答案的问题会说明证据不足；账号 A 无法检索账号 B 的文档；删除文档后不能继续召回其旧分块。

参考：[Supabase 混合检索](https://supabase.com/docs/guides/ai/hybrid-search)、[RAG 权限](https://supabase.com/docs/guides/ai/rag-with-permissions)。

## 二、适度增强现有单 Agent

增强重点是让检索问答更可靠，而不是增加角色或单独的任务工作台：

1. **理解追问**：结合有限的近期对话，将“它有哪些限制”“和另一个相比呢”等追问改写成可检索的独立问题。保留原问题，改写只用于检索，不能添加用户未表达的事实。
2. **拆分检索**：对于跨文件比较、多个子问题，最多拆成 3 个检索问题，统一结果去重、排序并限定上下文。简单问题沿用一次检索路径，避免固定增加模型调用。
3. **按需补查**：第一次结果缺失关键证据时，换关键词或读取命中片段的上下文；首版最多 2 轮检索。相关度只作为启发式信号，不能等同于答案置信度。仍无证据时如实说明。
4. **展示操作**：前端折叠展示“检索资料、补充检索、读取片段、生成回答”的状态、来源数和耗时，方便理解过程与定位错误；不展示内部思维链。

建议先提供两个内置只读工具：`searchKnowledge({ query })` 检索当前已选资源，`readDocument({ documentId, chunkId })` 获取已授权片段及有限上下文。用户身份、会话和资源范围由服务端注入，不允许模型自行选择用户或扩大检索范围。两者直接调用内部领域服务，无需工具协议层。

RAG 模式下，在生成文档结论之前必须取得检索结果；不能只依靠模型是否愿意调用工具。自动执行的首次检索与后续自主补查共用预算和事件记录。未选择文件/知识库时，不启动检索。

从 app/api/chat/route.ts 拆出 lib/agent/runtime.ts、tools.ts、events.ts；接口负责认证和请求边界，运行时负责模型-工具-结果循环，工具实现复用领域服务。

核心实体 AgentRun / AgentStep：记录会话归属、模型、状态、工具调用 ID、参数摘要、来源、错误分类与耗时；避免额外复制整份文件和敏感原文。继续使用普通聊天界面。

增加统一工具接口：参数 Schema、可访问资源范围、超时、结果大小。保留模型调用最多 5 轮的上限，另设工具调用次数、总时限和上下文预算；为最终回答预留一轮，触及上限时停止工具调用并根据已有证据作答。重复的工具名、参数和资源范围直接复用本轮结果，避免原地循环。仅对短暂故障进行有限重试，参数错误和无结果不能盲目重试。

状态：running -> completed / failed / cancelled / budget_exceeded。SSE 带 runId、stepId 与事件序号；保存已执行步骤，刷新后可查看记录。首版不承诺刷新后原生成任务仍在后台运行，也不自动重放工具；需要后台续跑时另做持久化执行队列。取消时尽可能传播至模型和工具，对不支持取消的调用显示真实终态。

本轮只新增检索与读片段两个只读工具。已有联网搜索继续受用户开关控制；文档证据不足时不能擅自联网，也不能把网页结果冒充用户文档来源。

验收：追问能定位当前资料；跨文件问题可拆分并合并证据；证据不足会补查或明确说明；参数错误、超时、预算耗尽均可结束；取消后旧结果不污染新会话。对同一组问题对比一次检索与 Agent 补查的效果和额外延迟，若没有收益则不默认增加步骤。

## 三、通用客户端的首版边界

产品内 Skill 暂不做，不增加 Skill 选择器、加载器或流程模板。保留已经安装的开发辅助 Skill，不将其当成聊天产品功能。

MCP 完全移出本轮范围，包括 Client、Server、Context7、服务配置、连接管理和相关 SDK；不保留为实施阶段的依赖。

普通聊天和用户文件 RAG 可独立使用。未选择文档时不检索知识库；入库或检索失败时给出明确提示，用户可重试或主动取消资料范围后继续普通聊天，不将失败静默伪装为有依据的回答。

引用 ID 由服务端分配并绑定本轮实际召回片段；回答中使用的 ID 需校验，区分“检索到的资料”与“回答引用的资料”。流式阶段的引用未经验证不应显示为已核实来源。文档内容只作为证据，不赋予其中的指令工具权限。

## 四、全栈链路和展示界面

数据库建议新增 KnowledgeBase、Document、Chunk、IngestionJob、AgentRun、AgentStep；记录文件与会话/知识库的关联。首版不需要专用报告实体。

API 服务继续使用 Next.js Route Handlers。文档解析/向量化由独立 Node worker 执行持久化任务，首版可以使用 PostgreSQL 任务表与任务锁，避免为了简历额外加入 Redis。不要把长任务放进 API 返回后的悬空 Promise；部署时保证 worker 真正有常驻执行环境。

前端在当前工作台上增加文件库与入库状态、会话检索范围选择、来源侧栏和折叠的检索操作记录。保持对话区为主，只有查看来源或调用记录时展开细节。

观测按 runId 关联入库、检索、模型调用和工具调用；分别记录检索耗时、模型首字/完整响应、工具耗时、失败原因。只有服务返回可靠 usage 时记录真实 Token/费用；未知值不写成 0。

部署交付包括数据库迁移、环境变量示例、Web/worker 启停、健康检查与一次可重现演示。实际测试权限隔离、文件删除、失败重试、工具范围与聊天降级，而不是仅检查生成文本里出现关键词。

## 实施顺序和可证明成果

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| P0 | 通用会话附件 RAG | 单个/多个选中文件可问答，来源可定位，权限及删除测试通过 |
| P1 | 可复用知识库与入库管理 | 相同文档无需每轮重传，处理状态及失败重试可恢复 |
| P2 | 适度增强单 Agent、保存执行记录 | 追问改写、有限拆分/补查及去重可验证，预算/超时/取消能结束，来源始终限于授权资源 |
| P3 | 评测、部署和简历定稿 | 同一套题和操作可重复演示，指标有测量说明与证据 |

准备 30-50 道自己标注的问题作为待建设评测集，覆盖正确召回、跨文件、无答案、权限边界；对比全文拼接、向量召回与混合检索。记录检索命中/排名、引用正确性、证据不足时的回答行为、延迟及 Token 使用。上述题量是建议，不是已经完成的评测规模。没有实测结果不写准确率提升或耗时下降百分比。
